# Skill: 摄入收件箱 (Ingest Inbox)

## 触发条件

- 用户说“处理 inbox”、“摄入新文件”、“check inbox”
- 用户将新文件拖入对话
- `raw/inbox/` 目录在对话开始或定时检查时发现非空

## 前置检查

1. 使用 Obsidian MCP 工具（如果可用）或直接列出 `raw/inbox/` 的内容
2. 如果为空，告知用户“收件箱为空”并结束
3. 如果不为空，列出待处理文件清单，询问用户“逐一处理”还是“全部处理”

## 执行流程（两段式）

### 第一段：分析

对于每个待处理文件：

1. 读取 `purpose.md` 和 `wiki/index.md` 了解当前知识边界
2. 使用 Obsidian MCP 搜索文件中的关键概念，获取已有页面的反向链接数据
3. 通读文件内容
4. 生成 `wiki/_analysis_[文件名].md`，包含：
   - 核心实体列表（建议页面名，标注是新增还是更新）
   - 核心概念列表（同上）
   - 与现有 Wiki 的链接点（基于 MCP 反向链接结果，列出将被更新的页面）
   - 矛盾发现（与 `foundations/` 中基线对照）
   - 知识缺口（文中提到但 Wiki 无页面的主题）
   - 发散性检查初稿（反面论点）
5. **暂停，等待用户确认**（可回复“继续”、“跳过”、“修改某处”）

### 第二段：生成

1. 创建或更新 `entities/`、`concepts/`、`topics/` 页面
   - 使用 `[[Wikilinks]]` 语法建立交叉引用
   - 概念页必须包含“反面论点与数据空白”小节
   - 所有断言必须可追溯到源文件
2. 更新 `wiki/index.md`（添加新页面条目）
3. 如果涉及领域认知变化，标记需要更新 `state.md`（触发 state-synthesis skill）
4. 在 `wiki/log.md` 追加操作记录
5. 将源文件从 `raw/inbox/` 移动到 `raw/archive/`
6. 删除 `_analysis_[文件名].md`

## 节奏控制

- 逐个处理时：每完成一个文件，简要报告（1-2句话），再处理下一个
- 批量处理时：先完成所有分析摘要，统一等待确认，再批量生成
