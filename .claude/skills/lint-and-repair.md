# Skill: 健康检查与修复 (Lint & Repair)

## 触发条件

- 用户明确要求“执行 Lint”、“健康检查”、“检查 Wiki”
- 夜间自动化维护触发
- 每次摄入超过 5 个新文件后，主动建议执行一次快速检查

## 工具使用优先级

1. 优先使用 Obsidian MCP 工具获取反向链接、标签统计
2. 如 MCP 不可用，回退到手动遍历页面
3. 如 llm-wiki 已部署，调用 `llm-wiki orphans` 和 `llm-wiki communities` 获取分析数据

## 检查清单

按顺序逐项执行，每项完成后标记 [已检查]：

- [ ] **孤立页面**：反向链接数为 0 的页面

  - 自动修复：为孤立页面寻找最相关的 3 个页面，建议添加 [[链接]]，用户确认后执行
- [ ] **死链接**：指向不存在页面的 [[Wikilinks]]

  - 自动修复：尝试找到最匹配的已有页面替换，或移除链接保留文本
- [ ] **矛盾信息**：不同页面中对同一事实的冲突描述

  - 修复方式：在冲突双方页面添加 `[CONTRADICTION: 参见 [[对方页面]]]` 标记，并在 state.md 的“活跃争论”中登记
- [ ] **过时内容**：`updated` 日期超过 90 天、且对应来源已被新文件覆盖的页面

  - 修复方式：标注 `[MAYBE_OUTDATED]`，提醒用户审查
- [ ] **知识缺口**：`index.md` 提到但无对应页面的主题、页面中频繁提及但无独立页面的概念

  - 修复方式：列出缺口清单，询问用户是否需要触发 deep-research skill
- [ ] **发散性检查缺失**：概念页面缺少“反面论点与数据空白”小节

  - 自动修复：为该概念生成一个基础的反面论点小节（标注 `[TODO: 待补充具体论据]`）
- [ ] **索引完整性**：`index.md` 中列出的页面与实际存在的页面是否一致

## 输出格式

检查完成后，生成分级报告：

### 🔴 严重（需立即处理）

（列出死链接、严重矛盾）

### 🟡 注意（建议处理）

（列出孤立页面、过时内容）

### 🟢 良好

（列出本次检查通过的项）

然后询问：“是否自动修复可修复的项目？”
