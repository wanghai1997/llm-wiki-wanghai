# 写入-门控 (Write-Time Gating)

## 触发条件

- 每次 Ingest 的分析阶段完成后、生成阶段开始前
- Lint 检查中发现陈旧或低质量页面时
- 夜间自动化维护触发

## 门控三问

分析每一条即将写入 Wiki 的知识断言之前，依次评估以下问题。

### Q1：该知识是否与 `foundations/` 中的持久事实冲突？

- 若冲突 → 标记 `[CONTRADICTION]` 而非直接覆盖（保留版本链）

### Q2：该知识是否提供了增量信息？

- 若重复已有 `consolidated` 断言 → 仅增加 `sources` 引用，不创建新页面
- 若为微调性补充 → 追加到已有页面的「最新进展」小节，不独立建页
- 若为全新概念或颠覆性发现 → 允许创建新页面，`status: draft`

### Q3：该知识的来源组合是否达到最低入库门槛？

- 单来源（一篇网络文章）：仅生成 `_analysis` 摘要，不入库
- 单来源（一篇顶刊论文）：入库但标记 `status: draft`，`confidence ≤ 0.85`
- 多来源（≥2 个独立来源）：正常入库，`confidence` 取较高值
- 多来源 + 教材/综述支撑：可标记 `status: consolidated`

## 执行输出

每次自动门控判定后，在分析摘要 `_analysis_[文件名].md` 中增加一个表格：

| 断言   | 决策       | 原因                             |
| ------ | ---------- | -------------------------------- |
| 断言 1 | 入库-draft | 单来源但来自顶刊                 |
| 断言 2 | 不入库     | 与 foundations/ 重复             |
| 断言 3 | 等待       | 缺乏足够来源支撑，待后续摄入验证 |

## 与现有 Skill 的关系

本 Skill 在 ingest-inbox 的「第一阶段→第二阶段」之间自动插入执行。
若 lint-and-repair 发现陈旧页面，触发重新评估。
