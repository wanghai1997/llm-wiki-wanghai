# Agent与AaaS

## 定义

[[黄仁勋]] 在 GTC 2026 演讲中预言：

> 每一家 SaaS（软件即服务）公司都将变成 **AaaS（Agent-as-a-Service，智能体即服务）公司**。

进一步把 [[OpenClaw]] 类比为"智能体计算机的操作系统"，与 Linux、HTML、Kubernetes 并列为企业必备的技术战略。

## Agent 计算特征

- 管理资源；访问工具、文件系统与大语言模型。
- 调度、定时任务；将问题逐步分解，并调用子智能体。
- 任意模态输入输出（语音、视频、文字、邮件）。
- 与"询问 AI 是什么、在哪里、怎么做"不同，Agent 让 AI 主动"创建、执行、构建"。

## 企业 IT 范式迁移

| 维度 | OpenClaw 之前 | OpenClaw 之后 |
| --- | --- | --- |
| 形态 | SaaS 工具 | AaaS（专精领域的 AI 智能体） |
| 角色 | 软件公司 + GSI/咨询 | 软件公司 + Agent 厂商 |
| 安全模型 | 用户登录、权限控制 | 策略引擎、网络护栏、隐私路由（NeMo Claw + Open Shield） |
| 工程师工作方式 | 人写代码 | "年薪 + Token 配额"，工程师 10× 效率 |

## 行业规模主张

- 黄仁勋：原本 2 万亿美元规模的企业 IT 产业，"即将成长为数万亿美元规模"。
- 每家企业未来同时是 Token 使用者（供工程师内部使用）和 Token 生产者（为客户提供服务）。

## 反面论点与数据空白

- **历史案例多次失败**：类似"无服务器架构终结运维""低代码终结开发"等强论断历史上多次出现，但实际呈现长期共存。Agent 终结 SaaS 同样可能高估替代速度。
- **"OS 类比"过强**：操作系统具备硬件抽象、调度、文件系统等明确语义；Agent 框架是否可比仍未结论。
- **OpenClaw "几周超越 Linux 30 年"修辞**忽视生态、社区、基础设施差距，是对开源治理的简化。
- **企业内部 Agent 的安全责任归属**：当 Agent 自主执行代码并接触敏感数据时，事故责任归用户、Agent 提供方还是云平台？合规框架尚未成熟。
- **年薪 + Token 配额**有阶级偏见：仅适合高薪知识工人；广义劳动力影响可能反向（替代而非放大）。
- **"工程师 10× 效率"**为黄仁勋估算，缺乏受控实验或独立基准。
- **"2 万亿 → 数万亿美元"**是营销级别预测；缺需求侧拆解。
