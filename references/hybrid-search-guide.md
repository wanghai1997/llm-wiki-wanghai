# 混合搜索升级指南

## 触发条件

**保持轻量搜索**（满足任一即继续用 Obsidian MCP）：

- Wiki 总页面数 ≤ 200
- 查询为简单事实型（如「交易成本理论由谁提出」）
- 查询结果在前 5 条中已满足需求

**升级到混合搜索**（满足任一即升级）：

- Wiki 总页面数 > 200
- 查询为关系型（如「哪些理论挑战了有效市场假说」）
- 查询需要跨多个知识簇综合
- 用户明确要求「深度搜索」

## 混合搜索方案（渐进式三选一）

### Step 1：链接遍历增强（零新依赖，优先使用）

**无需安装任何新工具。** 利用已部署的 Synapse MCP 工具，在查询时执行两项操作：

- **关键词搜索**：使用 `garden_forage` 在 Vault 中进行全文匹配（等价于 BM25 稀疏检索）
- **链接遍历**：基于已搜索结果，通过 `garden_read` 读取页面的 Wikilinks，沿链接关系扩展相关页面

> ⚡ 这一步**只利用已有的 `[[双向链接]]` 结构来发现相关笔记**，不对链接本身附加任何语义标签（如“导致”“反驳”）。它纯粹是检索层的扩展，与优化四的“弱关系注释”完全正交。

示例指令：

> “先用 garden_forage 搜索 ‘货币主义’，再将返回的每个页面里的 `[[...]]` 链接全部展开，把那些被频繁链接但尚未出现在搜索结果中的页面也加入待读列表。”

### Step 2：LightRAG 插件（页面数 200-500 时推荐）

安装 Obsidian 社区插件 `LightRAG`（一站式安装，零配置，但大型 Vault 索引耗时可能达 6 小时，建议在夜间执行）。

### Step 3：QMD + BM25 + 向量混合（页面数 500+ 时推荐）

在 VS Code 终端中执行：

```bash
# 安装 QMD
npm install -g qmd

# 构建混合索引
qmd collection add D:\llm-wiki-wanghai\wiki --name wiki
qmd embed

# 混合搜索测试
qmd search "有限理性 行为经济学" --fusion rrf
```

QMD 内置 BM25 + 向量 + RRF 融合 + LLM 重排序，且支持 MCP 服务器（CLAUDE.md 中已有引用）。
